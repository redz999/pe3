# Архитектура приложения (предложение v0.1)

## 1. Выбранный стек

Рекомендованный стек для MVP:
- **.NET 8 + C#**
- **WPF** для Windows Desktop UI
- Open XML SDK для работы с DOCX-шаблоном
- Экспорт PDF через отдельный адаптер (выбирается после теста совместимости)

Причины:
- нативная desktop-интеграция в Windows;
- удобная локальная работа с файлами и профилями;
- хорошая поддержка корпоративной эксплуатации.

## 2. Слои системы

1. **Presentation (WPF)**
   - Окна/диалоги
   - Привязки данных
   - Команды: открыть BOM, выбрать профиль, сгенерировать ПЭ3

2. **Application**
   - Сценарии use-case:
     - ValidateBom
     - BuildElementList
     - FillTemplate
     - ExportPdf
     - SaveProfile / LoadProfile

3. **Domain**
   - Модели и правила:
     - ElementRecord
     - GroupPrefix
     - DesignatorRange
     - NaturalSort

4. **Infrastructure**
   - Чтение `.xlsx`
   - Работа с `.docx`
   - Конвертация в `.pdf`
   - Файловое хранилище профилей (JSON)
   - Логирование

## 3. Ключевые модули

### 3.1 BomReader

- Считывает Excel BOM.
- Проверяет обязательные столбцы.
- Возвращает коллекцию нормализованных записей.

### 3.2 BomValidator

- Проверяет валидность структуры BOM.
- Формирует список ошибок/предупреждений.
- Останавливает сценарий генерации при критических ошибках.

### 3.3 ElementListBuilder

- Группирует элементы по префиксу обозначения.
- Выполняет естественную сортировку.
- Объединяет соседние обозначения в диапазоны при одинаковом Part Number.
- Готовит строки для ПЭ3 (Поз. обозначение / Наименование / Кол. / Примечание).

### 3.4 DocumentGenerator

- Заполняет титульные поля (ФИО, проект и т.д.).
- Заполняет таблицу элементов.
- При переполнении создаёт страницы по шаблону второго листа.
- Сохраняет лист регистрации изменений последним.

### 3.5 PdfExporter

- Конвертирует итоговый DOCX в PDF.
- Возвращает диагностическую ошибку, если PDF-экспорт недоступен.

### 3.6 ProfileStore

- Хранит настройки схемы в JSON.
- Поддерживает добавление новых параметров без миграционных поломок.

## 4. Формат профиля (черновик)

```json
{
  "profileName": "Э3_БлокПитания",
  "projectTitle": "Блок питания 24В",
  "author": "Иванов И.И.",
  "reviewer": "Петров П.П.",
  "normController": "Сидоров С.С.",
  "approver": "Кузнецов К.К.",
  "templatePath": "C:/Templates/pe3_template.docx",
  "outputDirectory": "C:/Projects/Output",
  "extraFields": {
    "department": "ОКБ-7"
  }
}
```

## 5. Основной сценарий работы

1. Пользователь выбирает профиль схемы.
2. Выбирает BOM-файл `.xlsx`.
3. Нажимает «Сгенерировать».
4. Система валидирует BOM.
5. Система строит строки перечня.
6. Система заполняет DOCX-шаблон.
7. Система сохраняет DOCX и PDF.
8. Пользователь получает отчёт по результату.

## 6. Риски и открытые вопросы

- Поддержка «Office 2003 и новее» конфликтует с нативным форматом DOCX
  (исторически Office 2007+). Нужна финализация требований по минимальному
  реально поддерживаемому набору форматов.
- Механизм стабильного экспорта PDF без установленного Word требует
  технологического выбора и проверки лицензирования.
