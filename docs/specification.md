# Спецификация требований (v0.1)

## 1. Назначение

Приложение автоматизирует формирование перечня элементов (ПЭ3) по ГОСТ 2.701-2008
для инженера-схемотехника, используя BOM-файл, экспортированный из Altium Designer.

## 2. Входные данные

### 2.1 BOM

- Формат: `.xlsx`
- Один лист в файле
- Обязательные колонки:
  - `Designator`
  - `Part Number`
  - `Quantity`
- Гарантии на входе:
  - нет объединённых ячеек,
  - нет формул,
  - нет скрытых строк.

### 2.2 Профиль схемы (настраиваемые параметры)

Для каждой схемы (Э3) пользователь сохраняет профиль настроек:
- Наименование проекта.
- ФИО разработчика.
- ФИО проверяющего.
- ФИО нормоконтролёра.
- ФИО утверждающего.
- Путь к шаблону Word.
- Дополнительные параметры (расширяемый блок).

## 3. Выходные данные

- Документ перечня элементов в формате `DOCX`.
- PDF-версия того же документа.

## 4. Шаблон документа

Шаблон Word состоит из трёх листов:
1. Лист 1: рамка и начало таблицы элементов.
2. Лист 2: продолжение таблицы элементов (используется для добавляемых страниц).
3. Лист 3: лист регистрации изменений (должен оставаться финальным листом).

Правило расширения:
- При переполнении таблицы создаются новые страницы по образцу второго листа.
- Новые страницы вставляются между первым листом и листом регистрации изменений.

## 5. Правила обработки BOM

1. В обработку берутся все строки BOM.
2. Элементы группируются по позиционным префиксам (`R`, `C`, `U`, ...).
3. Внутри группы применяется естественная сортировка обозначений (`R1 < R2 < R10`).
4. Соседние элементы с одинаковым `Part Number` объединяются в диапазон
   позиционных обозначений (например, `R1-R13`).
5. Обязательные поля результата:
   - Поз. обозначение
   - Наименование
   - Кол.
   - Примечание

## 6. Валидация и ошибки

- Если отсутствует хотя бы одна обязательная колонка BOM,
  генерация прерывается.
- Пользователь получает сообщение:
  «Неправильный состав BOM-файла. Требуются колонки: Designator, Part Number, Quantity».
- Опционально формируется отчёт об ошибках/предупреждениях обработки.

## 7. Нефункциональные требования

- Платформа: Windows 10/11.
- Локализация интерфейса: русский.
- Поддержка офисного окружения: Office 2003 и новее (учитывается при выборе
  механизма работы с DOCX/PDF).
- Пакетная обработка BOM — вне MVP, рассматривается в следующей версии.
- Фильтры исключения элементов — вне MVP, закладываются как расширяемость.
